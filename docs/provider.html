MeroProvider

The client, the passkey session and the default app

PropTypeWhat it does
minReleaseVersionstringThe oldest mero-tee release to trust, for example 2.3.109. This is shorthand for policy: { release: { minReleaseVersion } }.
policyCloudPolicyThe full attestation policy (profile, release source, verifyQuote, appHash). Takes precedence over minReleaseVersion.
allowMockbooleanAccept mock quotes (merod local, --dev clusters). The provider throws if minReleaseVersion, policy and allowMock are all missing.
servedByNodebooleanThe node serves this page. The node is then window.location.origin, and a passkey ceremony here opens a session bound to this app's package. ConnectButton skips the node field.
nodeUrlstringThe node to use when the page is not node-served. Without it, the provider uses the node kept from the last visit, or waits for connectToNode.
nodesstring[]Other nodes of the cluster. On 421 WRONG_NODE the client moves to the next one and repeats the request once.
appIdstringThe app instance that hooks default to.
sessionStoreSessionStoreWhere the session is kept. The default is localStorageSessionStore; memorySessionStore() keeps it for the tab's lifetime only.
passkeyPasskeyProviderThe WebAuthn prompt. The default is mero-js browserPasskey().
fetch, retryPassed through to CalimeroClient.
clientCalimeroClientUse this client instead of building one, for tests or custom setups.
onError(failure) => voidCalled with every failure that a hook or a sign-in reports.

useMero()

const {
  client,            // CalimeroClient | null (null until a node is known)
  nodeUrl, connectToNode, disconnect,
  session, accountId, isAuthenticated, isLoading,
  signIn,            // () => Promise<CalimeroSession | null>: an existing passkey
  signUp,            // (name) => Promise<CalimeroSession | null>: a new account and passkey
  signOut, signOutEverywhere,
  appId, setAppId,
  passkey, servedByNode, allowMock,
  failure,           // the last sign-in or session failure, described
  reportError,
} = useMero();

Sessions. A 1.0 session is a session token (v2.…) that lasts 15 minutes, plus a refresh token (rt_…) that lasts 30 days and can be used once.

  • The client refreshes by itself on a 401. One refresh is shared by every request waiting on it, because reusing a refresh token revokes the session (mero-js#318).
  • The provider saves every new session to sessionStore, so a reload resumes the session.
  • When a refresh is refused, hooks get LoginRequired, and the provider ends the session and sets failure.kind = 'login'.
  • mero is still on the value as a deprecated alias of client.
